# Розділ 6. Аналіз дискримінантів

Дискримінант — це спеціальний елемент, який використовується для параметризації об’єктів складених типів. Компоненти типу з дискримінантами можуть залежати від значення цих дискримінантів: наприклад, обмеження щодо підтипу компонента чи його початкове значення можуть визначатися значенням дискримінанта об’єкта. Дискримінанти також використовуються для опису варіантів типу запису з варіантами, тобто для визначення наявності певних компонентів запису. За винятком масивів, усі складені типи в Ada можуть мати дискримінанти. Отже, типи записів, захищені типи та типи задач, а також відповідні підтипи можуть містити дискримінанти.

Тип із дискримінантами є необмеженим – іншими словами, для нього не достатньо інформації для створення об’єкта; при оголошенні об’єкта такого типу необхідно вказати значення для дискримінантів за допомогою обмежень на дискримінанти. Наприклад:

```ada
type My_Record (Max Length : Positive) is
record
   Name : String (1 .. Max Length);
end record;

Obj : My_Record (30);
```

Оскільки властивості компонентів залежать від значень дискримінантів, об’єкт із дискримінантами є самодостатнім: значення дискримінанта визначає істинність певної інваріантної властивості об’єкта – наприклад, розміру масивного компонента. Саме тому значення дискримінантів не можна змінювати довільно, незалежно від значень компонентів, які від них залежать. Внаслідок цього дискримінанти об’єкта слід розглядати семантично як константи; на відміну від інших компонентів запису, їх не можна змінювати шляхом присвоєння чи передавати як параметри типу “out” під час виклику функцій.

Вищесказане чітко показує, що дискриміновані типи є механізмом параметризації, а дискримінанти обробляються подібно до параметрів під час створення об’єкта з таким типом. Ця аналогія поширюється також на синтаксис та семантику специфікацій дискримінантів і формальних параметрів.

Подібно до параметрів підпрограм, специфікації дискримінантів також можуть містити вирази за замовчуванням. Якщо у дискримінантів запису встановлені значення за замовчуванням, можна оголосити об’єкт цього типу без вказання явних обмежень; у такому разі об’єкт отримує свої значення дискримінантів з відповідних виразів за замовчуванням. Такий об’єкт називається необмеженим, і його можна змінити шляхом присвоєння нового значення всьому об’єкту – це змінить як значення дискримінантів, так і значення складових, які від них залежать.

Дискримінанти виконують подібну функцію для задач та захищених типів. У обох випадках їх можна використовувати для обмеження компонентів, а також сімейств записів. Також поширеною практикою є використання дискримінанта для визначення пріоритету об’єкта задачі, щоб різні об’єкти одного типу мали різні пріоритети.

У Ada83 дискримінанти мають бути дискретного типу. Це зумовлено поширеним використанням дискримінантів як виразів у операторі `case` для опису варіантів певного типу запису. Ada95 вводить поняття доступного дискримінанта, який дозволяє параметризувати об’єкт вказівником на інший об’єкт. Однак такі доступні дискримінанти не можуть використовуватися для керування варіантами, адже вони не є дискретними. Тип із доступним дискримінантом є обмеженим типом, оскільки присвоєння для об’єктів, які містять вказівники на інші об’єкти, не має сенсу.

## 6.1 Аналіз дискримінантів

На перший погляд аналіз дискримінантів не додає особливої складності компілятору. Безпосередньою сферою дії дискримінантів є визначення типу, яке включає оголошення решти компонентів запису, але не включає саме специфікування дискримінантів. Здається, що Семантичному аналізатору достатньо лише (1) внести дискримінанти до сфери дії оголошення типу, (2) перевірити, чи вказані значення за замовчуванням для всіх або ж для жодного з дискримінантів [AAR95, Розділ 3.7(11)], та (3) перевірити, чи імена дискримінантів не використовуються у виразах за замовчуванням інших дискримінантів. Проте насправді все завжди є складнішим.

Наприклад, вирази за замовчуванням потрібно аналізувати у спеціальному режимі, оскільки вони відповідають *обмеженням, що застосовуються до кожного об’єкта* [AAR95, розділ 3.3.1(9)]: для кожного об’єкта, оголошеного без явних дискримінантів, значення за замовчуванням має обчислюватися заново. Іншими словами, якщо значенням за замовчуванням є виклик функції, цей виклик має виконуватися для кожного об’єкта відповідного типу, а не лише під час аналізу оголошення типу. Проте компілятор повинен виконати всі перевірки на коректність саме у момент визначення типу. У результаті, подібно до способу аналізу генеративних одиниць, вирази за замовчуванням у оголошенні типу аналізуються у спеціальному режимі, який виключає їх розширення. Внаслідок цього вираз за замовчуванням залишається позначеним як непроаналізований; проте семантичний аналізатор обчислює статичні вирази та виконує відповідні операції “заморожування” (див. детальний коментар у пакеті `Sem`). Семантичний аналізатор пов’язує такий попередньо проаналізований вираз із визначаючою сутністю дискримінанта, аби його можна було легко отримати у місцях використання – тобто під час оголошення необмежених об’єктів даного типу.

Ще одним аспектом семантичного аналізу, який ускладнюється наявністю дискримінантів, є обробка агрегатів [AAR95, розділ 4.3]. Агрегат для типу запису має містити значення для всіх компонентів цього типу. Отже, якщо у типі є дискримінанти, їхні значення також мають бути вказані. Якщо ж тип містить варіантну частину, агрегат повинен визначати всі компоненти саме того варіанту, який відповідає заданим значенням дискримінантів. Щоб компілятор міг ідентифікувати потрібний варіант та зібрати всі необхідні компоненти, дискримінанти в такому агрегаті мають бути статичними. У випадку вкладених варіантних частин семантичний аналізатор повинен рекурсивно перебирати структуру типу запису, щоб перевірити, чи є вирази, що відповідають кожному дискримінанту, статичними; визначити, які саме варіанти обираються за заданими значеннями дискримінантів; а також перевірити, чи вказано значення для всіх компонентів у кожному з цих варіантів. Наприклад, розглянемо наступний приклад:

```ada
declare
   type T_Company is (Small, Big);
   type T_Record (Company Kind    : T_Company;
                  Num_Departments : Natural) is
   record
      Num_Workers : Positive;
      case Company is
         when Small =>
            Has_Benefits : Boolean;
         when Big =>
            case Num_Departments is
               when 1 .. 10 =>
                  Value : Integer;
               when others =>
                  null;
         end case;
      end case;
   end record;

   Obj_1 : T_Record (Small, 1);
   Obj_2 : T_Record (Big, 7);
   Obj_3 : T_Record (Big, 15);
begin
   Obj_1 := (Num_Workers => 2, Has_Benefits => False);
   Obj_2 := (Num_Workers => 100, Value = 10000);
   Obj_3 := (Num_Workers => 150, Value = 15000);  --  ERROR
end ;
```

У прикладі наведено оголошення типу запису з вкладеними варіантами (рядки 7–17), три оголошення об’єктів (рядки 20–22) та три оператори, які ініціалізують ці об’єкти за допомогою агрегатів (рядки 24–26). Третій агрегат є некоректним: на момент оголошення об’єкта (рядок 22) кількість відділів була обмежена значенням 15, і це значення використовується у вкладеній частині з варіантами (рядки 11–16) для позначення того, що для такого типу компанії додаткова інформація не потрібна.

Для обробки загального випадку аналіз агрегованого запису здійснюється шляхом побудови карти, яка пов’язує кожен компонент із відповідним виразом у агрегаті. Спочатку ця карта містить самі дискримінанти; згодом до неї додаються всі компоненти, що зустрічаються у обраних варіантах (детальніше описано у пакеті `Sem_Aggr` та підпрограмі `Gather_Components`).

Агрегація розширень для типів ускладнює аналіз, адже компоненти можуть походити від предків заданого типу. У такому випадку значення дискримінантів використовуються для навігації по варіантних частинах цих предків.

Для збору списку необхідних компонентів. У всіх випадках аналізатор перевіряє, чи були вказані значення для всіх компонентів, чи мають вони правильний тип, а також чи відсутні зайві значення.

## 6.2 Аналіз дискримінантів у похідних типах

При успадкуванні типу з дискримінантами дискримінанти батьківського типу можуть успадковуватися, обмежуватися під час успадкування або перейменовуватися шляхом введення нових дискримінантів. Нижче наведено основні правила успадкування [AAR95, розділи 3.4(11), 3.7(13–15)].

– Якщо дискримінанти не вказані, похідний тип успадковує дискримінанти батьківського типу (неявно у тому ж порядку, з тими самими специфікаціями та значеннями за замовчуванням). У цьому випадку похідний тип просто копіює повну декларацію батьківського типу; компоненти похідного типу відповідають один до одного компонентам батьківського типу.
– Якщо у похідного типу є дискримінанти, а батьківський тип не є типом з тегами, кожен дискримінант похідного типу має використовуватися у обмеженні, яке визначає підтип батьківського типу.
Останнє правило гарантує, що за відсутності спеціальних вказівок структура похідного типу є ідентичною структурі його батьківського типу. Генератор коду лише має посилатися на фізичну структуру оригінального типу. Для обробки можливих переіменувань, які можуть виникнути під час успадкування, визначаючий елемент дискримінанта у похідному типі містить атрибут `Corresponding_Discriminant`, який дозволяє Семантичному аналізатору знайти початковий дискримінант у батьківському типі (див. коментар у реалізації функції `Build_Derived_Record_Type`).

У разі наявності умов представлення ця проста модель стає непридатною для використання. Адже мова Ada дозволяє використовувати умови представлення у похідному типі `D`, які визначають іншу структуру запису, ніж у його *батьківському* типі `P`. Внаслідок цього відповідний компонент може знаходитися у двох різних позиціях – у батьківському та похідному типах. Через це ці два типи не можуть мати спільних оголошень своїх компонентів; для них необхідно формувати повністю незалежні дерева оголошень. Семантичний аналізатор GNAT створює копію всього дерева оголошень компонентів типу `P` та формує повне оголошення похідного типу `D`. Отже, тип `D` виглядає як самостійний записовий тип із власними умовами представлення (якщо такі є). Сутність типу `D` вказує на те, що це похідний тип, та посилається на батьківський підтип `P`.

Умови представлення не можуть бути визначені для типів із тегами, оскільки механізм диспетчеризації та поліморфізм вимагають однакового формату представлення для спільних компонентів усього класу.

## 6.3 Дискримінатори

Аналогія між дискримінантами та параметрами стає ще очевиднішою під час розгляду процесу ініціалізації об’єктів. Якщо у складному типі є компоненти, які мають явний чи неявний вираз ініціалізації, об’єкти цього типу необхідно ініціалізувати під час створення. Для цього компілятор генерує процедури ініціалізації для кожного такого типу та викликає їх щоразу, коли оголошується об’єкт даного типу. Якщо у типі є дискримінанти, процедура ініціалізації має параметри, які відповідають цим дискримінантам один до одного. У середовищі GNAT ці параметри називаються **дискриміналами**; між кожним дискримінантом та його відповідним дискриміналом існує семантичний зв’язок. Виклик процедури ініціалізації включає список параметрів, який є копією значень дискримінантів, використаних (явно чи неявно) під час оголошення об’єкта. Деталі щодо процедур ініціалізації розглядаються у окремому розділі. Наприклад, розглянемо таке оголошення типу:

```ada
type Rec (D : Integer) is record
    Value : Integer : = D;
    Name  : String (1 .. D) = (1 .. D = '!');
end record;
```

Відповідна процедура ініціалізації виглядає так:

```ada
procedure Init_Proc (Obj : in out Rec; D : Integer) is
begin
   Obj.Value := D;
   Obj.Name  := (1 .. D => '!');
end ;
```

Оголошення *Obj1 : Rec (17)* призводить до генерування наступного виклику:

```ada
Init_Proc (Obj1, 17);
```

## 6.4 Підсумок

Дискримінант є спеціальним елементом, який виступає у ролі параметра для об’єктів певного типу. Значення за замовчуванням дискримінанта має особливе значення: воно дозволяє об’єктам цього типу не мати жодних обмежень. Для коректної обробки дискримінантів компілятор Ada повинен приділяти особливу увагу аналізу значень за замовчуванням; ці значення мають обчислюватися саме в момент оголошення об’єкта, а не типу. Крім того, оскільки клаузули представлення в Ada дозволяють похідному типу визначати зовсім іншу структуру запису порівняно з батьківським типом, похідний тип зобов’язаний копіювати всі компоненти батьківського типу. Під час аналізу агрегатів записів необхідно використовувати вказані значення дискримінантів для визначення наявності та властивостей інших компонентів об’єкта, щоб перевірити семантичну коректність всього агрегата.
