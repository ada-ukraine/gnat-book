# Розділ 8. Аналіз заморожування

Ada дозволяє програмістам вказувати явну інформацію щодо кінцевого представлення певної сутності [AAR95, Розділ 13]. Момент, коли це представлення повністю визначається, називається `Freezing_Point`. Очевидно, якщо представлення не вказано явно, компілятор змушений приймати якесь стандартне рішення. Коли сутність „заморожується“, це призводить до „заморожування“ усіх залежних від неї сутностей. У наступній таблиці наведено список таких залежних сутностей, які також „заморожуються“ під час заморожування певної конструкції.

| Об’єкт, який заморожується | Що заморожується |
|-------------------------|-----------------|
|                         |                 |
| Статичний вираз        | Сутності у виразі та їхні типи, а також тип самого виразу |
| Нестатичний вираз      | Тип виразу |
| Алокатори              | Визначений підтип кваліфікованого виразу або позначення підтипу |
| Об’єкт                  | Відповідний підтип (за винятком відкладених констант) |
| Підтип                  | Відповідний тип |
| Похідний підтип        | Батьківський підтип |
| Тип із компонентами     | Підтипи компонентів |
| Обмежений масив        | Підтипи індексів |
| Підпрограми та елементи | Підтипи параметрів та результатів |
| Тегований тип          | Відповідний тип класу |
| Розширення тегованого типу | Батьківський тегований тип |
| Тип класу              | Відповідний тегований тип |
| Генерична інстанціація  | Підтипи параметрів |

GNAT створює вузол `Freeze_Entity` у точці, де відбувається „заморожування“ сутності, а також встановлює вказівник від самої сутності на цей вузол. Пізніше ці вузли обробляються розширювачем для генерації коду та даних, які мають бути доступними лише після „заморожування“ представлення типу (наприклад, підпрограма ініціалізації). Крім того, вони використовуються Gigi для визначення моменту, коли об’єкт має бути ініціалізовано. Якби компілятор GNAT повністю дотримувався моделі Ada, він б створював вузли „заморожування“ для всіх сутностей, але це було б дещо надмірно. Тому „заморожуються“ лише ті сутності, чиї характеристики представлення можна визначити на етапі оголошення (див. пакет `Freeze`).

Хоча Умовний посібник з мови Ada визначає обмеження щодо використання окремих елементів мови, компілятору необхідно приділяти особливу увагу деяким деталям. Ці деталі розглядаються у наступних розділах.

## 8.1 Типи та підтипи заморожування

Усі оголошені типи мають вузли «заморожування». Це стосується також анонімних базових типів, створених для обмежених оголошень типів; у таких випадках визначений ідентифікатор є першим підтипом цього анонімного типу. Очевидним винятком із цього правила є типи доступу – заморожування типу доступу не призводить до заморожування його відповідного підтипу. Крім того, усі перші підтипи також мають вузли «заморожування». Для інших підтипів вузли «заморожування» потрібні лише у разі, якщо відповідний базовий тип ще не був заморожений; якщо ж базовий тип вже заморожений, вузли «заморожування» не потрібні, адже для підтипу в будь-якому разі не можуть бути визначені клаузули представлення.

Типи та підтипи заморожуються внаслідок: 1) оголошень об’єктів, 2) тіл, які знаходяться в тій самій декларативній області (наприклад, тіло підпрограми), та 3) завершення відповідної декларативної частини. Коли користувачем визначений тип заморожується, це зазвичай призводить до заморожування всіх сутностей, від яких він залежить (для значень за замовчуванням передбачено особливий режим обробки, про який йтиметься пізніше). Наприклад, заморожування визначення підтипу призводить до заморожування всіх похідних типів від цього підтипу аж до кореневого типу. Імпліцитні типи, а також типи та підтипи, створені семантичним аналізатором чи розширювачем для відображення базової семантики мови Ada, заморожуються у момент заморожування відповідного похідного типу. Наприклад, визначення обмежених типів компілятор GNAT внутрішньо перетворює на визначення імпліцитного *анонімного базового типу* та визначення похідного типу.

```ada
type T is new Integer;
  --  Internally transformed by the compiler into:
  --     type TB is new Integer;
  --     subtype T is TB;
type T is array (1 .. 10) of ...;
  --  Internally transformed by the compiler into:
  --     subtype TD is Integer;
  --     type TB is array (TD range <>) of ...;
  --     subtype T is TB (1 .. 10);
```

У цьому прикладі `TB` та `TD` є імпліцитними типами, які будуть заморожені після того, як їхній похідний тип `T` буде заморожений. Заморожування імпліцитних типів, що вводяться через оголошення компонентів (тобто обмеження на компоненти), не потребує затримки, адже семантичний аналізатор перевіряє, чи батьківські типи цих підтипів вже заморожені перед тим, як заморожувати сам запис (див. підпрограму `Build_Discriminated_Subtype`).

## 8.2 Заморожування виразів

Загалом, присвоєння імені сутності в будь-якому виразі призводить до «заморожування» відповідного типу [AAR95, розділ 13.14]. Проте компілятор повинен приділяти особливу увагу значенням за замовчуванням, які використовуються у дискримінантах та обмеженнях компонентів запису; їх слід «заморожувати» саме в момент оголошення відповідних об’єктів (а не в момент визначення типу). Наприклад:

```ada
type T_Int is new Integer;
type T_Name is array (T_Int range <>) of Character;

type T (Max : T_Int) is            --  Do not freeze T_Int here
   record
      Name   : T_Name (1 .. Max);  --  Do not freeze T_Int here
      Length : T_Int := Max;       --  Do not freeze T_Int here
   end r e c o rd;

My_Object : T (30);                --  Freeze T_Int, T_Name, T
                                   --  and My_Object
```

Відповідно, значення за замовчуванням, які використовуються у параметрах підпрограм, мають визначатися лише після того, як підпрограма буде „заморожена“. Для процедур це відбувається при наявності їх тіла; для функцій же компілятор повинен також враховувати виклики функцій, які зустрічаються у ініціалізації об’єктів.

## 8.3 Заморожування об’єктів

Прості об’єкти заморожуються у момент їх оголошення. Потрібно бути особливо обережним із відкладеними константами, які неможливо заморозити до моменту повного оголошення константи. Об’єкти з динамічними адресними умовами піддаються заморожуванню з затримкою. У момент заморожування Gigi генерує код для обчислення початкового виразу (якщо він є).

Захищені типи потребують особливої обережності під час обробки, адже їх визначення розширюється у визначення типу-запису. Наприклад:

```ada
protected type PO (Discriminants) is
   ...
private
   <Private_Data>;  --  <1>
end PO;
--  Internally transformed by the GNAT compiler into:
--
--  type poV (Discriminants) is new Limited_Controlled with
--     record
--        <Private_Data>  --  <2>
--        _object : Run_Time_Data_Type (<Num_Entries>);
--     end record;
--  ...
```

У зв’язку з цим підтипи компонентів у визначеннях типу з захистом (рядок 1) не потребують заморожування. Дії заморожування відповідають еквівалентним компонентам у визначенні записового типу (рядок 2); згідно з правилами заморожування мови Ada це має відбуватися пізніше, а саме на момент першого оголошення об’єкта типу *poV*.

## 8.4 Заморожування підпрограм

Формальні параметри заморожуються в момент заморожування специфікації відповідної підпрограми; тому немає жодної потреби у їхньому відкладеному заморожуванні. Специфікації підпрограм заморожуються на момент їх оголошення, за винятком випадків, коли один або кілька формальних типів чи тип результату мають відкладене заморожування та ще не були заморожені. Це також стосується випадків, коли формальний тип доступу посилається на тип, який ще не заморожений. Тіла підпрограм заморожують усі елементи.

## 8.5 Заморожування пакетів

Правила заморожування для пакетів є досить зрозумілими. Після завершення обробки пакета бібліотеки відбувається заморожування кожної сутності, оголошеної всередині нього; винятком є неповні та приватні типи, для яких заморожування відкладається до моменту знаходження повного опису типу. Щодо неповних типів потрібно проявляти особливу обережність, адже їх розміщення у тілі пакета є допустимим [AAR95, Розділ 3.10.1(3)]. Крім того, оскільки семантичний аналізатор зберігає сутності як з часткового, так і з повного перегляду, він також повинен поширювати інформацію про заморожування з повного перегляду на частковий (див. підпрограму `Find_Type_Name`).

У випадку локальних пакетів кінець тіла пакета спричиняє такий самий ефект, як і тіло підпрограми: він призводить до блокування сутностей, оголошених перед ним у межах того ж декларативного розділу [AAR95, Розділ 13.14(3)].

## 8.6 Заморожування універсальних одиниць вимірювання

Зрозуміло, оскільки для узагальнених одиниць не генерується жоден код, вони не мають вузлів заморожування; ці вузли необхідно генерувати у екземплярах. У екземплярах на рівні бібліотеки відбувається заморожування всього наприкінці відповідної частини коду. Проте у локальних екземплярах заморожуються лише: (1) їхні реальні параметри та їхні вирази за замовчуванням (якщо такі є), а також (2) сутності, оголошені перед ними у межах однієї декларативної частини. Така поведінка запобігає передчасному заморожуванню глобальних типів, які використовуються в узагальнених одиницях. Крім того, компілятор повинен приділяти особливу увагу ранній ініціалізації локальних пакетів. Наприклад:

```ada
procedure Example is
   generic
   ...
   package G is
      ...
   end G;

   procedure Local is
       package I (...) is new G;   --  Early instantiation
                                   --  Freezing point (freeze i)
   begin
      ...
   end;

   package body G is
      ...
   end G;
begin
   ...
end Example;
```

На етапі початкової ініціалізації семантичний аналізатор створює екземпляр специфікації (що є необхідним для подальшого аналізу підпрограми `Local`); відповідний екземпляр створюється під час наступного проходу обробки (див. опис у розділі 7.4). Проте семантичному аналізатору необхідно додати вузол «заморожування», аби визначити для GiGi правильний порядок обробки пакетів (див. підпрограми `Install_Body` та `Freeze_Subprogram_Body`).

## 8.7 Підсумок

Мова Ada дає програмістам можливість вказувати явну інформацію щодо кінцевого представлення певної сутності. Компілятор створює вузол `Freeze_Entity` у місці, де сутність “заморожується”, та встановлює вказівник від самої сутності до відповідного вузла заморожування. Пізніше ці вузли обробляються розширювачем для генерації пов’язаного коду та даних. Хоча У посібнику з мови Ada визначені точки заморожування, компілятору необхідно приділяти особливу увагу: 1) анонімним, неявним та неповним типам; 2) значенням за замовчуванням; 3) захищеним типам; 4) генеричним одиницям. Ці аспекти були розглянуті в цьому розділі.
